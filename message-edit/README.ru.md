# Message Edit

Редактирование пользовательского сообщения в **той же сессии**, без fork:

1. Клиент останавливает текущий ответ и отправляет правку с номером исходного сообщения.
2. Host в `agent/pre-step` заменяет суффикс модельной поверхности пустым `developer/message`. В событии обязательны `turn`, `step` и `message.source`.
3. В модель попадают история **до** выбранного сообщения и исправленное сообщение с сохранёнными вложениями. Служебный заголовок в модель не передаётся.
4. UI скрывает заменённые ходы только в соответствующей панели разговора.

Если исходное сообщение уже исключено из поверхности (например, предыдущей правкой или компакцией), правка отклоняется. Обновите разговор и выберите актуальное сообщение. Некорректная правка не отправляется как обычный запрос со старой историей.

## Ограничения

- Это исключение из контекста, **не физическое удаление**: append-only журнал DSH сохраняет исходные события. Просмотр журнала/экспорт и инструменты чтения истории могут показывать старые записи.
- Выполненные команды, изменения файлов, состояние плагинов и другие внешние эффекты не откатываются.
- Протокол использует обычную очередь prompt: приём запроса клиентом не означает, что серверная правка уже выполнена. Ошибка host отображается как ошибка хода.
- Замена поверхности происходит в pre-step. Последующая ошибка провайдера не восстанавливает старую ветку автоматически.
- UI скрывает целые ходы (turn). Если несколько пользовательских сообщений попали в один ход, визуально может скрыться и сохранённая часть этого хода; модельная поверхность обрезается точно от выбранного сообщения.

## Проверка

Требуется установленный DSH (тесты используют настоящие Session и V4 codec, без запросов к модели):

```sh
npm test
npm run check
```

По умолчанию установка DSH определяется через `npm root -g`. Для другой установки:

```sh
DSH_ROOT=/path/to/@deepseek-ai/dsh npm test
```

## Подключение исправлений

Этот пакет содержит готовые JS entry points: отдельной сборки TypeScript/Vite нет. Если профиль использует ссылку на этот каталог, повторная установка пакета не нужна. Перезагрузите host-плагин через управление плагинами (если доступно) либо перезапустите `dsh web`, затем обновите страницу GUI. Одно обновление браузера не гарантирует перезагрузку серверного модуля.

Фикс не переписывает некорректные события, которые могла создать прежняя версия. Первую проверку лучше выполнить в новой тестовой сессии.

Ручная проверка после загрузки исправлений:

1. В тестовой сессии отправьте несколько сообщений с различимыми ответами.
2. Измените среднее сообщение: ранняя история должна остаться, выбранное сообщение и хвост — исчезнуть, новая версия — получить ответ.
3. Повторно измените исправленное сообщение, затем более раннее сохранённое сообщение.
4. Перезагрузите страницу и убедитесь, что результат не изменился.
5. Повторите с вложением; в соседней открытой сессии сообщения не должны скрываться.

Версия 1.5.1 исправляет ошибку `developer/message turn must be a non-negative safe integer` и связанные проблемы повторного редактирования.
