# Commands bridge (`@uptick7/dsh-commands-bridge`)

Мост между markdown-командами и реестром slash-команд Harness + страница **Settings → Commands**.

## Установка

Опубликовано на npm как [`@uptick7/dsh-commands-bridge`](https://www.npmjs.com/package/@uptick7/dsh-commands-bridge); объявлен диапазон `engines.dsh: ">=0.2.1-rc.1 <0.3.0-0"`.

Установка в профиль (замените `web` на имя своего профиля), затем перезапуск host:

```sh
dsh plugin --profile web add @uptick7/dsh-commands-bridge
```

Либо установка из веб-GUI: **Плагины** (Plugin Manager) → найти `@uptick7/dsh-commands-bridge` → установить; включите бандл, если менеджер не сделал это сам.

Из этого репозитория, без npm: склонируйте его и добавьте в `package.json` профиля и зависимость, и имя бандла:

```json
{
  "dependencies": {
    "@uptick7/dsh-commands-bridge": "link:/путь/к/dsh-plugins/commands-bridge"
  },
  "dsh": {
    "profile": {
      "bundles": [
        "@uptick7/dsh-commands-bridge"
      ]
    }
  }
}
```

## Что делает

- Регистрирует в `ctx.commands` команды из markdown-файлов:
  - **Агентные** — `~/.dsh/commands` (корень самого агента);
  - **Общие** — `~/.agents/commands` (общие для всех агентов на машине);
  - **Проектные** — `<рабочая директория сессии>/.agents/commands` (свой скоуп на агента, имеет приоритет над глобальными с тем же именем).
- Вызов `/name аргументы` читает файл заново, подставляет `$ARGUMENTS` и `$1`–`$9` (если плейсхолдеров нет — дописывает аргументы в конец) и отправляет промпт агенту как обычное пользовательское сообщение (`agent.steer`). Запуски пишутся в лог сессии (`command/run` / `command/done`).
- Команды с описанием и argument-hint автоматически появляются в меню `/` композера.
- Изменения файлов в отслеживаемых директориях подхватываются на лету (fs.watch + рескан).

## Страница Settings → Commands

- Группы: «Команды агента», «Общие команды», «Команды проекта» (по рабочей директории каждой открытой сессии), «Команды плагинов» (только просмотр: то, что зарегистрировали другие плагины — `/plan`, `/compact` и т.п.; их жизненным циклом управляет собственный плагин).
- Для каждой команды: `/имя`, argument-hint (если задан), описание (если задано) и тумблер включения/отключения.
- Отключённые команды остаются на диске, но не регистрируются в реестре. Состояние тумблеров хранится в JSON-файле (по умолчанию `~/.agents/commands-bridge.json`, ключ `<kind>:<имя>` — общий для всех проектных директорий).

## Формат файла команды

```markdown
---
description: Краткое описание для меню и страницы команд
argument-hint: KEY [cases]
---

Текст промпта. Аргументы: $ARGUMENTS, позиционные: $1 $2
```

Frontmatter необязателен; имя команды — имя файла без `.md` (нижний регистр, `a-z0-9_-`).

## Конфиг (cordis.patch.yml)

```yaml
- insert:
    - id: commands-bridge
      name: '@uptick7/dsh-commands-bridge'
      config:
        globalDirs: ['~/.agents/commands']   # общие для всех агентов директории
        agentDirs: ['~/.dsh/commands']       # директории этого агента
        projectSubdir: '.agents/commands'    # поддиректория в рабочей директории сессии
        stateFile: '~/.agents/commands-bridge.json' # файл состояния тумблеров
```

## Ограничения

- Проектные команды привязываются к рабочей директории на момент создания агента; смена директории внутри живой сессии не отслеживается (обновится после переоткрытия сессии).
- Тумблер для проектной команды действует на все проекты (ключ без пути).
- Страница настроек — часть веб-GUI; в профилях без `commands`/`webServer` соответствующие возможности просто не активируются.
- Позиционные аргументы `$1`–`$9` делятся по пробелам; кавычки снимаются только вокруг целого слова. Для всего текста аргументов используйте `$ARGUMENTS`.
