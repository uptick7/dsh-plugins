# Группы панели (`@uptick7/dsh-sidebar-groups`)

Пользовательские группы для боковой панели dsh web: **папки для воркспейсов** (рабочих директорий) и **папки для сессий внутри каждого воркспейса**. Чисто слой отображения — сессии и воркспейсы не переименовываются и не переносятся на диске, а членство в группах привязано к стабильным идентификаторам хоста (`workspaceId`, `sessionId`), поэтому переименование сессии или воркспейса не ломает дерево.

## Установка

Опубликовано на npm как [`@uptick7/dsh-sidebar-groups`](https://www.npmjs.com/package/@uptick7/dsh-sidebar-groups); объявляет `engines.dsh: ">=0.2.1-rc.1 <0.3.0-0"`.

Установите в профиль (замените `web` на имя своего профиля), затем перезапустите хост:

```sh
dsh plugin --profile web add -w @uptick7/dsh-sidebar-groups
```

Или из веб-интерфейса: **Plugins** (Plugin Manager) → поиск `@uptick7/dsh-sidebar-groups` → установить.

Из этого репозитория без npm: склонируйте его и добавьте зависимость и имя бандла в `package.json` профиля:

```json
{
  "dependencies": {
    "@uptick7/dsh-sidebar-groups": "link:/путь/к/dsh-plugins/sidebar-groups"
  },
  "dsh": {
    "profile": {
      "bundles": [
        "@uptick7/dsh-sidebar-groups"
      ]
    }
  }
}
```

## Что делает

Плагин заменяет штатную панель Workspaces группированным деревом:

```
▾ Клиенты              (группа воркспейсов; иконка: несколько папок)
  ▾ Сайт Acme          (воркспейс; иконка: одна папка, как в шатной панели)
      ▾ Баги           (группа сессий; иконка: несколько сообщений)
          фикс логина  (сессия, как сейчас — без иконки)
          …
      рефактор css     (сессия вне групп)
  ▸ Внутренние утилиты (воркспейс)
▸ Архив                (группа воркспейсов)
```

- **Вложенность** разрешена в обоих доменах (контекстное меню → *Создать подгруппу), но ничего не вкладывается само: дерево ровно такое, каким вы его сделали. Отступ — 12 px на уровень.
- **Иконки**: у группы воркспейсов — несколько папок, воркспейс сохраняет штатный вид с одной папкой, у группы сессий — несколько сообщений, сессии остаются без иконок. Точки статуса (выполняется / ждёт подтверждения / есть непрочитанное завершение), относительное время и маркер закрепления остаются на строках сессий.
- **Drag-and-drop**: сессия → группа сессий (только того же воркспейса — сессия не может покинуть свой воркспейс), воркспейс → группа воркспейсов, группа → другая группа (смена родителя; циклы отвергаются). Сброс на полосу внизу панели вынимает элемент из группы; сброс воркспейса на другой воркспейс меняет порядок в реестре хоста и переносит его в группу цели, если та отличается. Недопустимые цели показывают курсор «нельзя».
- **Контекстные меню**:
  - строки групп (правый клик или `…`): *Создать подгруппу*, *Переименовать*, *Переместить в группу ▸*, *Удалить группу* (подгруппы поднимаются на уровень удаляемой группы, элементы становятся негруппированными; сессии и воркспейсы не затрагиваются);
  - строки сессий: штатное меню сессии продолжает работать (закрепить, переименовать, форк, копировать id, архив — его диалоги живут в оверлеях кадра и переживают замену), плюс подменю *Группа ▸* (назначить / убрать / новая группа);
  - строки воркспейсов: собственное меню рендерит вклады общего меню — включая «открыть в приложении» от других плагинов — и добавляет свои *Переименовать* / *Удалить* (штатные пункты писали бы в приватное состояние диалогов заменённой панели, поэтому они отфильтровываются и реализуются здесь поверх публичного API, с диалогами подтверждения).
- **Шапка**: поиск (мгновенные совпадения по метаданным плюс отложенный контентный поиск хоста), настройки вида (порядок «по обновлению» / «по имени»; архивные скрыты / показаны / только они), новая группа проектов, добавить воркспейс (составной выбор директории заполняет ту же «дыру», что и штатная панель).
- Корзина «Без воркспейса» ведёт себя как ещё один контейнер и может иметь собственные группы сессий.
- Черновая **Новая сессия** сохраняет первую строку своего воркспейса и не перетаскивается.
- **Settings → Группы сессий**:
  - переключатель *Группированная боковая панель* — снимает регистрацию этого браузера и мгновенно возвращает штатную панель без удаления плагина;
  - счётчики групп и связей, путь к файлу хранилища;
  - *Убрать устаревшие ссылки* — снимает членство, указывающее на удалённые воркспейсы/сессии (удаление регистрации оставляет группу на месте; повторное добавление воркспейса получает новый id, поэтому старые ссылки требуют этой очистки).

## Хранение

Группы живут в одном JSON-файле на хосте (по умолчанию `~/.dsh/sidebar-groups.json`, ключ конфига `stateFile`):

```json
{
  "version": 1,
  "rev": 4,
  "groups": {
    "0f1e…": { "id": "0f1e…", "name": "Клиенты", "kind": "workspace", "parent": null, "scope": "" },
    "9a2b…": { "id": "9a2b…", "name": "Баги", "kind": "session", "parent": null, "scope": "<workspaceId>" }
  },
  "membership": {
    "workspace:<workspaceId>": "0f1e…",
    "session:<sessionId>": "9a2b…"
  }
}
```

Группа воркспейсов всегда имеет `scope: ""`; группа сессий несёт id воркспейса (или `""` для корзины «Без воркспейса»), сессии которого она может содержать. Все изменения уходят через `POST /sidebar-groups/apply` как проверяемые атомарные пачки операций — хост единоличный авторитет, каждый ответ возвращает канонический документ, поэтому несколько открытых вкладок сходятся к одному состоянию. Раскрытость, режим порядка и фильтр архивных — browser-local (как в штатной панели); порядок сессий внутри контейнеров: закреплённые сверху, далее по обновлению/имени.

Файл никогда не трогает названия сессий и воркспейсов и сами директории: удаление файла или плагина возвращает штатную панель без каких-либо последствий.

## Конфиг (cordis.patch.yml)

```yaml
- insert:
    - id: sidebar-groups
      name: '@uptick7/dsh-sidebar-groups'
      config:
        stateFile: '~/.dsh/sidebar-groups.json' # хранилище документа групп
```

## Как подключается

- Регистрирует компонент в single-слоте `sidebar.workspaces` (объявлен оболочкой боковой панели, заполнен штатным браузером `ui-workspace`); динамически зарегистрированный entry выигрывает слот. Затенение меняет только того, кто рендерит слот: штатный браузер остаётся зарегистрированным и продолжает объявлять свои «сиденья», поэтому occupant'ы (часы расписания, «дыра» выбора директории) продолжают работать. Плагин собственных сидений не объявляет — реестр отвергает дубли деклараций.
- Всё остальное — публичный API: `ctx.sessions`, `ctx.workspaces`, `ctx.uiWorkspace`, `ctx.uiSession`, `ctx.remoteAccess`, `ctx.contextMenus`, `ctx.locale`, `shell.overlay`, `settings.section`.

## Ограничения

- Штатные «показать ещё» (watermarks) и hover-карточки не воспроизводятся; раскрытый контейнер показывает все свои сессии.
- Архивирование сессии с активной работой выдаёт отказ хоста тостом; штатный диалог «остановить и архивировать» принадлежит заменённой панели — для этого потока переключитесь на штатный вид в настройках.
- Меню воркспейса при активном группированном виде рендерится плагином; вклады других плагинов появляются, но два штатных пункта, чьи диалоги умерли вместе с заменённой панелью, отфильтровываются (они реализованы заново поверх публичного API).
- Ручной порядок сессий (перетаскивание на конкретную позицию) не сохраняется: порядок — закрепления + свежесть/имя. DnD служит для членства в группах, а не для сортировки.

## Разработка

```sh
cd sidebar-groups
npm test        # node --test; покрыты модель и маршруты хоста
npm run check   # проверка синтаксиса
node dev-activation-harness.js  # материализует client.js с заглушками и запускает apply() для отладки ошибок загрузки
```

`groups-ops.js` — чистая модель операций (валидация, применение, поиск устаревших ссылок), общая для хост-половины и тестов; `client.js` самодостаточен и импортирует только React — по конвенции репо для клиентских плагинов.
